# Search, GEO and AEO readiness

Implemented: descriptive titles and summaries, canonical URLs, Open Graph/Twitter previews, visible product facts, a concise installation/FAQ guide, matching JSON-LD SoftwareApplication/WebSite/FAQPage data, sitemap.xml, robots.txt, and a factual llms.txt summary. No invented reviews, ratings, statistics, or unsupported platform claims are used. The player app is noindex and excluded from the sitemap; the public-facing guide explains its features.

The supplied HTML verification file is served at `/google2af4e1ed3191321d.html`. Do not rename it to the downloaded filename containing `(3)`. An HTML verification filename is not a valid substitute for a Google meta-tag verification token.

## Private preview limitation
The website remains private at the owner's request. Authentication prevents Google and other crawlers from fetching the content, verification file and sitemap. These files prepare the site for a future public release; they do not bypass access controls. No Search Console verification or sitemap submission has been claimed.

## When public access is explicitly approved
1. Verify the chosen final domain and update canonical, social, sitemap and llms URLs together if it changes.
2. Confirm the verification file returns its exact content without sign-in, then complete Search Console verification with the owner's Google account.
3. Submit the sitemap and inspect representative URLs.
4. Validate structured data and mobile usability, measure real performance, and fix observed issues.
5. Keep app version, features and answers accurate as releases change.

GEO (generative engine optimization) and AEO (answer engine optimization) use these same truthful, accessible content foundations. `llms.txt` is optional and does not guarantee ingestion. Structured data does not guarantee rich results; FAQ rich results have eligibility restrictions.
